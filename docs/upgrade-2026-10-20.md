# 线上更新：2026-10-20

小云，这次正常更新就是：**确认数据库里有两张新表，替换前后端镜像，启动这两个服务。** 不需要重新安装 OJ，不换 MySQL 镜像，也不移动题库、附件或评测数据。

有一个首次更新的例外：你给的旧备份中，共享密钥和 Nacos 密码达不到新版安全要求。如果线上已调整好，这一步可以跳过；否则需要做一次密码调整，并重建原评测机容器，让它读取新密码。**评测机镜像仍用原来的。**

本次镜像，平台 `linux/amd64`：

```text
yunyunjuan/sxuoj-backend:contest-security-20261020
yunyunjuan/sxuoj-frontend:contest-security-20261020
```

最终 digest、源码提交和验收结果见[发布清单](contest-security-release-2026-10-20.json)。

本版已按要求直接发布。已有前后端构建、部署兼容检查通过；完整 HTTP 验收仍有失败断言（调整解封时间后匿名查看题面），未继续排查或重测，不能视为全部接口验收通过。

## 1. 在原来的部署目录操作

进入服务器上原来放 `docker-compose.yml` 和 `.env` 的目录。以下命令沿用这套部署；原来额外使用了 `-p`、多个 `-f` 或 `--env-file` 的，继续带原参数。

先把这两个文件备份到服务器的受限目录，并确认已有可恢复的数据库备份。记下原前后端的镜像 ID，保留原镜像：

```bash
docker inspect -f '{{.Image}}' hoj-backend
docker inspect -f '{{.Image}}' hoj-frontend
docker compose ps
```

把本次交付目录也上传到服务器，例如 `/opt/sxuoj-update-20261020`。它包含 `deploy/`、`docs/` 和校验清单。下面只需把这个路径改成实际路径：

```bash
UPDATE_DIR=/opt/sxuoj-update-20261020
docker pull yunyunjuan/sxuoj-backend:contest-security-20261020
docker pull yunyunjuan/sxuoj-frontend:contest-security-20261020
```

## 2. 在 MySQL 执行建表命令

使用 Navicat 打开 `hoj` 库，先执行：

```sql
SHOW COLUMNS FROM hoj.contest LIKE 'id';
```

你提供的库结果是 `bigint unsigned`，对应执行交付目录里的 **`deploy/contest-security-schema.sql`**。可以直接在 Navicat 打开这个 SQL 文件并运行。

这只会创建 `contest_access_policy`、`contest_protected_resource` 两张缺失的表。昨天已经建过的不用重建，已有解封时间和资源记录会保留。**不要清空这两张表，也不用修改 `contest`、`problem`、用户或提交表。**

如果现场 `contest.id` 类型不同，改用能自动匹配类型的命令：

```bash
python3 "$UPDATE_DIR/deploy/contest_policy_migrate.py" --mysql-container hoj-mysql --database hoj --apply
```

建完后运行一次只读检查；看到 `ready: true` 再继续：

```bash
python3 "$UPDATE_DIR/deploy/contest_policy_migrate.py" --mysql-container hoj-mysql --database hoj
```

## 3. 检查现有密钥是否能直接使用

```bash
python3 "$UPDATE_DIR/deploy/prepare_upgrade.py" --env-file .env
```

它只读文件，不改密码，也不打印密码。六项都为 `true` 时，直接去第 4 步。

如果 `jwt_strong`、`judge_token_strong` 或 `nacos_password_strong` 为 `false`，先暂停对外提交，等正在判题的任务结束。在维护窗口停止旧后端和评测机，再做下面这次调整；多机评测也要先停对应客户端：

```bash
docker compose stop hoj-backend hoj-judgeserver
```

```bash
python3 "$UPDATE_DIR/deploy/prepare_upgrade.py" --env-file .env \
  --backend-image yunyunjuan/sxuoj-backend:contest-security-20261020 \
  --mysql-container hoj-mysql --nacos-database nacos --write
```

它会保存原 `.env`，准备需要的强密钥并更新 `.env`。原 MySQL、Redis、邮件等其他参数不变。输出的 `private_package` 是这次私密备份的路径，不要把这个目录发到群里或提交 Git。

若输出 `nacos_sql_required: true`，在 Navicat 打开该路径下的 `nacos-password.sql` 并执行，确认 `updated_existing_account` 为 **1**。这个 SQL 只改 `.env` 对应的现有 Nacos 账号，不创建新账号，不改 OJ 用户密码。结果为 0 时先停止，检查账号或是否重复执行，不能带着未生效的新密码启动后端。

然后用原镜像重建一次 Nacos，等它恢复健康：

```bash
docker compose up -d --no-deps --force-recreate --pull never hoj-nacos
docker compose ps hoj-nacos
```

如果工具提示变量引用、重复配置或别名冲突，先按提示整理 `.env`，不要手动删掉校验或关掉 Nacos。JWT 密钥变化后，已有用户需要重新登录。

## 4. 换前后端镜像

打开原 `docker-compose.yml`，只改这两项 `image`：

```yaml
hoj-backend:
  image: yunyunjuan/sxuoj-backend:contest-security-20261020

hoj-frontend:
  image: yunyunjuan/sxuoj-frontend:contest-security-20261020
```

这只是告诉你改哪两行，**不要用这几行覆盖整个 Compose 文件**。原端口、网络、后端卷、Nacos、数据库和评测机配置都保留。

新版前端已兼容原 `BACKEND_SERVER_HOST`、`BACKEND_SERVER_PORT`，也避开了原 `./1015:/usr/share/nginx/html/` 挂载；不再需要手动复制 dist。旧 `1015` 目录不用删除，原挂载可以先留着。

先启动后端并等到健康：

```bash
docker compose up -d --no-deps --no-build --pull never hoj-backend
docker inspect -f '{{.State.Health.Status}}' hoj-backend
```

**如果第 3 步改过共享凭据**，此时还要用新 `.env` 重建原评测机，让它重新连接 Nacos：

```bash
docker compose up -d --no-deps --force-recreate --pull never hoj-judgeserver
```

有多台评测机时，每台都更新相同的 Nacos 客户端密码并重建原容器。后端启动会把共享判题令牌发布到原来的 `hoj-prod.yml`，不要用只含一个 token 的文件覆盖 Nacos 的完整配置。确认评测机重新注册、能判题后，再启动前端并恢复对外访问：

```bash
docker compose up -d --no-deps --no-build --pull never hoj-frontend
docker compose ps
```

没有改共享凭据的日常更新，不需要重建 Nacos 和评测机。整个过程不要运行 `docker compose down -v`，不要换数据库镜像或删除原卷。

## 5. 打开网站确认这几件事

1. 浏览器强制刷新，后台名称为“保密赛”，设置里只有解封时间。
2. 没验证密码的账号看不到比赛内容标签；正确密码可看题，结束后封存，到解封时间再公开。
3. 封禁一个专用测试账号，确认比赛内榜、外榜和滚榜不再显示它；解禁后正常恢复。
4. 用专用测试比赛试删：取消、空密码、错密码都不能删除；输入当前管理员自己的账号密码才成功。
5. 普通题库、图片和附件能打开；提交一份已知正确程序，确认评测机给出正常判题结果。

解封时间没填的旧保密赛会继续封存，填好时间并保存即可。需要立即公开时，把解封时间改为当前或已过去的时间，但不能早于比赛结束时间。

## HTTPS 和多机评测

原来由外层 Nginx/网关负责 HTTPS 的，保留原网关和证书，前端容器继续 `USE_HTTPS=false`。若直接让前端容器提供 HTTPS，需要 `USE_HTTPS=true`，把原证书和私钥只读挂到 `/etc/nginx/certs/fullchain.pem`、`/etc/nginx/certs/privkey.pem`；原映射仍为 `8082:443` 时，再设 `PUBLIC_HTTPS_PORT=8082`。

多机评测继续使用原来的内网通信地址。MySQL、Nacos、Redis、判题接口只放行实际需要访问的服务器，不能因为用了 Docker 就把这些端口向所有公网地址开放；远程评测机仍需要能访问配置里的数据库地址。交付中的本地隔离测试 Compose 不能直接拿来覆盖线上 Compose。

## 出问题先怎么做

先暂停对外访问并保留数据库。已经启用保密赛后，不能回到不认识保密策略的旧后端，否则封存题目可能重新暴露。选择同样支持保密鉴权的已验证镜像，不能靠删策略表解决。

若卡在第 3 步且尚未启动新版，可用私密目录里的 `previous.env` 和 `rollback-nacos-password.sql` 配对恢复配置；恢复 Nacos 密码后也要重建使用它的客户端。不要用恢复整库的方式回退应用，避免丢失新提交。
