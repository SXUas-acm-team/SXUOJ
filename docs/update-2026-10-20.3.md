# 修复评测失败和图表空白

这次替换前后端镜像即可，不需要执行 SQL，也不需要修改 `.env`、服务密码或评测机镜像。上一版的手动解封、封存按钮继续保留。

## 修复了什么

- 评测机正常返回 JSON 后，后端无法把响应还原成对象，抛出异常并误报“Failed to connect the judgeServer”。本次明确声明响应类的 JSON 构造器，修复这个兼容问题。
- 评测服务明确返回失败时，后端更新记录缺少提交 ID，导致错误状态无法写到对应提交。本次补齐。
- ECharts 只加载了核心，没有加载柱状图、折线图等模块，造成首页周统计、ACM/OI 排名等图表空白，排名页还会在读取数据前中断。本次加载页面实际需要的模块，继续使用本地打包资源。

## 怎么更新

把原 Compose 中两个服务的镜像改为：

```yaml
# hoj-backend
image: yunyunjuan/sxuoj-backend:contest-security-20261020.3
# hoj-frontend
image: yunyunjuan/sxuoj-frontend:contest-security-20261020.3
```

在原 Compose 目录执行，原有额外参数继续带上：

```bash
docker compose pull hoj-backend hoj-frontend
docker compose up -d --no-deps --force-recreate hoj-backend hoj-frontend
```

刷新浏览器；页面仍使用旧资源时按 `Ctrl+F5`。之前已经错误标成“提交失败”的记录不会自动重判，可以在管理员提交管理中对受影响记录执行重判。

生产备份只用于本地隔离验证，没有连接或修改生产库。验证结果和发布镜像摘要记录在同目录的 `contest-security-release-2026-10-20.3.json`。
