# 恢复管理员手动解封、封存

这次只恢复比赛管理功能，不再改动 Nacos 启动逻辑；沿用 `.1` 后端的旧部署兼容修复。数据库新表已经创建，无须再执行 SQL。

在比赛编辑页打开“保密赛”后，已保存的比赛会显示 **立即解封**、**立即封存**。管理员确认后立即生效，不用再点保存，也不会把表单里尚未保存的其他字段一起提交。团队比赛的编辑页也有相同按钮。

- **立即解封**：只允许比赛结束后操作，所有人可查看题目、榜单等比赛内容，登录用户可赛后提交。
- **立即封存**：立即清除解封时间，赛后内容重新限制访问；以后需要重新解封或重新设定时间。
- 定时解封输入框继续保留，修改时间后仍需点击页面“保存”。新比赛须先保存保密赛设置，再使用即时操作。
- 权限沿用比赛管理规则：后台由超级管理员或具备后台角色的比赛所有者操作；团队比赛由超级管理员、比赛所有者或团队负责人操作。

把原 Compose 的两处镜像替换为：

```yaml
# hoj-backend
image: yunyunjuan/sxuoj-backend:contest-security-20261020.2
# hoj-frontend
image: yunyunjuan/sxuoj-frontend:contest-security-20261020.2
```

在原 Compose 目录执行，原有附加参数继续带上：

```bash
docker compose pull hoj-backend hoj-frontend
docker compose up -d --no-deps --force-recreate hoj-backend hoj-frontend
```

管理员页面刷新后即可看到按钮。前后端需要一起替换，否则旧后端没有即时操作接口。保留原 `.env`、数据库、附件、日志挂载和评测机。
