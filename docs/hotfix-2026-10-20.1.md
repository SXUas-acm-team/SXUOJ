# 后端启动兼容修复：只换镜像

适用于替换 `contest-security-20261020` 后出现以下报错的原部署：

```text
Nacos requires an explicitly configured strong NACOS_PASSWORD.
```

这次恢复不需要上传工具、修改 `.env`、更改服务密码或重建评测机。保留当前前端和其他服务，只把原 Compose 中 `hoj-backend` 的镜像改为：

```yaml
image: yunyunjuan/sxuoj-backend:contest-security-20261020.1
```

然后在原 Compose 目录执行，原来使用过额外 `-f`、`-p`、`--env-file` 参数的继续带上：

```bash
docker compose pull hoj-backend
docker compose up -d --no-deps --force-recreate hoj-backend
docker compose logs --tail=80 hoj-backend
```

数据库新表已经建好，本补丁不执行建表或迁移。

兼容处理：

- Nacos 客户端沿用原来的真实密码，由 Nacos 服务正常认证，不因本地长度规则拒绝旧部署。
- 后端缺少符合要求的 JWT 密钥时，自动生成强随机密钥，保存在原日志卷的 `.runtime-secrets/jwt.key`，以后重启继续使用。不要把该文件当普通日志清理。已经配置的强密钥继续有效；签名密钥变化时，用户重新登录即可，用户密码不变。
- 判题客户端优先沿用已有令牌，不要求更改原评测机密码，也不会在每次启动时随意轮换现有令牌。

此热修仅针对启动兼容。按要求跳过完整测试执行，进行编译和代码复核；不代表前一版本尚未完成的完整接口验收已经通过。
